# 网页游戏角色选择页设计规格

日期：2026-09-28

## 1. 目标

将当前 Figma 中的角色选择页面还原为一个可独立运行的桌面网页交互界面，并为后续接入网页游戏保留清晰接口。

第一版只实现角色选择流程、按钮状态、商店占位提示、临时首页和临时游戏占位页。复杂背景与角色美术使用原始图片；UI 控件由 React、TypeScript 和 CSS 重建，不能把整张 Figma 页面作为不可交互的截图使用。

## 2. 技术方案

- 构建工具：Vite
- UI 框架：React
- 类型系统：TypeScript
- 样式：普通 CSS
- 测试：Vitest 与 React Testing Library
- 字体：通过本地项目依赖打包 Montserrat，不依赖运行时访问 Google Fonts或用户系统字体
- 第一版不使用 React Router
- 第一版不实现 CSS 动画，但保留可扩展的类名和组件边界

## 3. 范围

### 3.1 第一版包含

- 高还原度角色选择页面
- 五个角色：PIKO、Riff、BONGO、NIBBY、MIRA
- 角色卡直接选择
- 左右箭头循环选择
- SELECT 确认角色
- 临时首页
- 临时游戏占位页
- 三个货币加号的商店未开放提示
- 所有按钮的 Default、Hover、Pressed、Keyboard Focus 和 Disabled 状态
- 桌面浏览器等比缩放
- 图片预加载、失败占位和必要的禁用状态
- 鼠标与键盘操作

### 3.2 第一版不包含

- 角色切换动画
- 按钮回弹等装饰动画
- 手机和平板布局
- 正式商店业务
- 正式游戏场景
- 账号、存档和后端接口
- 音效和背景音乐
- React Router

## 4. 页面流程

应用包含三个页面状态：

```text
临时首页
   ↓ 进入角色选择
角色选择页
   ↓ SELECT
临时游戏占位页
```

- 应用刷新后默认进入角色选择页，便于直接展示核心成果。
- 角色选择页左上角返回按钮进入临时首页。
- 临时首页的“进入角色选择”按钮返回角色选择页。
- SELECT 将当前角色保存为已确认角色，然后进入临时游戏占位页。
- 临时游戏占位页显示已确认角色的名称和缩略图。
- 从临时游戏占位页返回角色选择页时保留原角色选择。
- 页面切换使用 React 状态，不改变浏览器 URL。

## 5. 状态模型

```ts
type Page = "home" | "hero-select" | "game-placeholder";

type HeroId = "piko" | "riff" | "bongo" | "nibby" | "mira";

interface Hero {
  id: HeroId;
  displayName: string;
  backgroundSrc: string;
  logoSrc: string;
  cardSrc: string;
  disabled?: boolean;
}
```

应用级状态：

- `currentPage`：当前页面。
- `selectedHeroId`：角色选择页中当前角色。
- `confirmedHeroId`：进入游戏占位页时确认的角色。
- `isStoreNoticeOpen`：商店提示是否打开。
- `storeNoticeTrigger`：打开提示的货币加号，用于关闭后恢复焦点。
- `assetLoadState`：每个角色素材的加载状态。

所有角色相关视觉区域都从同一个 `selectedHeroId` 派生，组件不能保存相互独立的角色副本状态。

## 6. 组件结构

```text
App
├─ TemporaryHomePage
├─ HeroSelectPage
│  ├─ BackButton
│  ├─ CurrencyGroup
│  │  └─ CurrencyCounter ×3
│  ├─ HeroIdentity
│  ├─ CarouselArrow ×2
│  ├─ HeroCardList
│  │  └─ HeroCard ×5
│  ├─ SelectButton
│  └─ StoreUnavailableDialog
└─ GamePlaceholderPage
```

### 6.1 组件职责

- `App`：保存应用级页面和角色状态，协调页面切换。
- `TemporaryHomePage`：提供进入角色选择页的入口，并显示当前选择摘要。
- `HeroSelectPage`：组合选人页，不复制业务状态。
- `CurrencyCounter`：显示货币信息；加号打开商店占位提示。
- `HeroIdentity`：显示当前角色名字素材及关联文本。
- `CarouselArrow`：按角色数组顺序循环切换。
- `HeroCardList`：渲染五个角色卡。
- `HeroCard`：显示交互状态和选择状态。
- `SelectButton`：确认当前角色；必要素材未加载时禁用。
- `StoreUnavailableDialog`：可访问的商店未开放模态框。
- `GamePlaceholderPage`：显示已确认角色并允许返回。

## 7. 角色选择规则

角色顺序由单一数据数组定义。左右箭头使用模运算循环：

- 第一个角色向左切换到最后一个角色。
- 最后一个角色向右切换到第一个角色。
- 点击角色卡直接选中对应角色。
- 当前角色卡仍然可获得焦点，不把 Selected 等同于 Disabled。
- 重复选择当前角色不产生冗余状态更新。

## 8. 控件与键盘交互

所有可点击控件必须使用语义化 HTML `<button>`，禁止使用带点击事件的普通 `<div>` 模拟按钮。

统一状态：

- Default：正常状态。
- Hover：提高亮度、边缘或阴影强度，不做位移动画。
- Pressed：按下期间降低亮度并缩放至约 98%，释放后立即恢复。
- Keyboard Focus：使用 `:focus-visible` 显示清晰焦点环。
- Disabled：降低透明度和饱和度，显示不可用光标，不执行点击回调。

键盘规则：

- Tab 和 Shift+Tab 按视觉与 DOM 顺序移动焦点。
- Enter 和空格激活按钮。
- 角色区域获得焦点时，左右方向键循环切换角色。
- Escape 关闭商店提示。
- Disabled 控件不进入 Tab 顺序且不响应激活键。

## 9. 商店占位提示

三个货币加号共用一个模态框，固定文案为：

```text
商店功能暂未开放
```

模态框行为：

- 点击“知道了”关闭。
- 点击遮罩关闭。
- 按 Escape 关闭。
- 打开后焦点进入“知道了”按钮。
- 打开期间背景控件不可操作。
- 关闭后焦点返回触发提示的货币加号。

不使用浏览器原生 `alert()`。

## 10. Figma 还原与素材策略

### 10.1 Figma 来源

- PIKO 画板：`11:2`
- Riff 画板：`46:39`
- BONGO 画板：`48:76`
- NIBBY 画板：`50:113`
- MIRA 画板：`51:150`

### 10.2 图片内容

以下内容从 Figma 或现有本地素材提取：

- 五个角色的复杂背景和人物合成图
- 五张角色卡人物图
- 货币图标中无法合理用 CSS 重建的美术内容
- 角色名字透明 PNG

现有角色名字素材：

```text

assets/hero-logos/riff-transparent.png
assets/hero-logos/bongo-transparent.png

```

### 10.3 原生网页内容

以下内容使用 HTML、CSS 或 SVG 重建：

- 按钮底板、圆角、描边、渐变、阴影和高光
- 标题、副标题和货币数字
- 返回箭头、轮播箭头、加号和选择标记
- 左侧可读性遮罩和底部暗色遮罩
- 焦点环和禁用反馈

不得把整张 Figma 画板截图作为交互页面背景。不得擅自重新生成缺失的复杂角色或背景素材。提取出的资源使用语义化文件名，不使用 Figma 节点 ID 作为最终文件名。不得删除或覆盖现有素材。

## 11. 桌面缩放

- 逻辑画布固定为 `2048 × 1152`。
- 统一缩放系数：

```ts
const scale = Math.min(
  viewportWidth / 2048,
  viewportHeight / 1152,
);
```

- 舞台始终居中并完整显示。
- 不进行非等比拉伸。
- 不裁切角色、卡片或按钮。
- 非 16:9 窗口使用深紫黑色留边。
- 窗口尺寸改变时重新计算缩放。
- 第一版最低验收尺寸为 `1280 × 720`。

## 12. 素材加载与错误处理

- 进入选人页时预加载五个角色的背景、名字和卡片素材。
- 当前角色必要素材未加载完成时 SELECT 禁用。
- 未完成加载的角色卡显示主题化占位底色。
- 单个素材失败时显示缺图占位，不显示浏览器破图图标。
- 控制台记录失败路径和素材类型。
- 单个角色资源失败不能阻断其他角色的切换和选择。
- 加载成功后恢复相关控件状态。

## 13. 临时页面视觉

### 13.1 临时首页

- 使用与角色选择页一致的深紫游戏主题。
- 显示项目标题和当前角色摘要。
- 包含“进入角色选择”按钮。
- 不引入额外复杂背景或动画。

### 13.2 临时游戏占位页

- 显示已确认角色的名字和缩略图。
- 主要文案格式：`{角色名} 已准备就绪`。
- 次要文案：`游戏内容正在开发中`。
- 包含“返回角色选择”按钮。

## 14. 测试与验收

### 14.1 自动测试

使用 Vitest 和 React Testing Library验证：

- 点击每张角色卡都能正确切换。
- 左右箭头按照数据顺序循环。
- SELECT 将正确角色带入游戏占位页。
- 从占位页返回后角色选择保持不变。
- 返回按钮进入临时首页。
- 临时首页能够重新进入选人页。
- 三个货币加号都能打开同一个商店提示。
- Escape 能关闭商店提示。
- 模态框关闭后焦点返回原触发按钮。
- Disabled 控件不执行回调。
- Enter 和空格能够激活按钮。
- 当前角色必要素材未加载完成时 SELECT 禁用。
- 单个素材加载失败不会阻断其他角色。

### 14.2 浏览器人工验收

检查尺寸：

- 1920 × 1080
- 1600 × 900
- 1366 × 768
- 1280 × 720
- 非 16:9 桌面窗口

检查行为：

- 鼠标连续快速切换不会造成状态错位。
- Tab 顺序与视觉顺序一致。
- 焦点环清晰且未被容器裁切。
- 每个可见按钮都有明确点击结果。
- 禁用控件不会响应鼠标或键盘。
- 商店提示不会与背景控件同时响应输入。
- 页面完整显示，无拉伸和非预期裁切。
- 与 Figma 对比主要位置、尺寸、色彩和视觉层级。

## 15. 后续扩展接口

第一版组件边界应允许后续增加：

- CSS 角色切换动画
- 按钮回弹和光效动画
- React Router 页面路由
- 正式游戏场景
- 商店页面
- 音频系统
- 存档和账号数据

角色确认逻辑保持单一入口，例如：

```ts
function confirmHero(heroId: HeroId): void;
```

后续接入游戏引擎时，只替换该入口的消费者，不重写角色选择 UI。

## 16. 完成标准

只有同时满足以下条件才视为第一版完成：

- React、TypeScript 和 CSS 工程能够正常启动及构建。
- 五个角色均可通过卡片和循环箭头选择。
- 所有可见按钮都有实际结果和完整交互状态。
- SELECT 正确进入对应角色的临时游戏占位页。
- 左上角返回按钮进入临时首页。
- 三个货币加号显示正确占位提示。
- 键盘可以完成主要操作。
- 画面在规定桌面尺寸下完整显示。
- 没有擅自生成复杂背景或角色素材。
- 没有删除或覆盖用户现有文件。
- 自动测试通过，生产构建成功。
